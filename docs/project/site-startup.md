# 全站启动与导航

## 移除全局粒子后的合并修复

当前根布局通过 `getBlogEntryRoute()` 解析默认笔记地址，并将同一个 `blogHref` 传给 `SplashScreen` 与 `Navbar`，不能只给组件补一个硬编码默认值。全局 Field 已停用，启动流程不再等待 `fieldReady`，第二阶段改名为 `preparing`，只用于有上限的资源准备，不显示全局粒子。首页头像阶段、子页跳过头像、跳过按钮、9 秒 hydration 失败兜底和 noscript 可访问性保留。

下文包含移除全局粒子前的历史设计与测量，涉及 Field、`particles` 阶段或普通/谱场模式的内容不代表当前行为，也不能作为本次修复的运行证据。

## 启动顺序

1. 每次完整进入或刷新首页，都先展示头像、光环与进度动画。动画至少 2.2 秒；首屏可见图片的 `decode()`、字体及 Field 首帧参与就绪判断，资源等待最多 4 秒。进度条是开场动效，不代表下载百分比。
2. 首页第一阶段之后，以及直接进入或刷新其他页面时，隐藏页面控件，展示同一个全站粒子场景 0.5–2 秒。其他页面跳过头像动画，在粒子阶段有上限地等待当前页图片、字体、Field 和小屋状态；在 hydration 前根据入口路径决定可见层，避免头像闪现。重要资源提前完成时取短时长；超时后仍可浏览。没有第二个 Field 实例，没有在揭幕时集中创建效果。
3. 揭幕后恢复导航、内部滚动容器和播放器。手机只在第二阶段显示轨迹，进入页面后沿用原来的移动端背景策略与文档滚动。站内软导航保留已经就绪的布局，不重播开场；刷新和直接打开页面按入口执行：首页走第一、第二阶段，其他页面只走第二阶段。不再读写 `sessionStorage.hasSeenSplash`，旧标记不会绕过资源准备。

“跳过开场”立即显示页面，后台预热继续。`prefers-reduced-motion` 或显式保存的普通模式跳过第二阶段。新访客默认 Field，保留普通模式偏好；存储失败时仍能切换。HTML 中的 9 秒兜底与 noscript 样式避免 hydration 失败造成永久不可见。

## 哪些资源提前准备

- 共享导航清单的八个入口由 `router.prefetch()` 依次启动，手机无需先展开菜单。笔记直接预取服务端解析的默认文章，保留 `/blog` 原有跳转。Next 的 prefetch 没有完成 Promise，不把“已发起”当成“已就绪”。导航 Link 继续负责缓存失效后的预取。
- 小屋 JS、3.18 MiB 压缩源资源、贴图解码、GLTF 解析和拾取 BVH 在开场准备。直接进入小屋时由当前场景加载，避免预热再解析一份模型。一次待用的 CPU 模型最多保留 60 秒，首次访问转移所有权；后续访问从源缓存创建新资源，失败清除缓存并允许重试。离开路由释放 GPU、纹理、几何和索引，不共享已释放的模型。
- 原 Octree 构建存在秒级同步任务，改为 three-mesh-bvh 的间接索引，并在模型组之间让出主线程。真实 GLB 的双面射线测试与原始三角形 raycast 对照，避免以性能换取拾取错误。
- 音乐页代码提前导入，首次使用的两套着色器通过 `compileAsync()` 编译，后台暂停动画。无 WebGL 时保留播放器控制。是否能异步编译还取决于浏览器的 `KHR_parallel_shader_compile` 支持。
- 番剧 metadata 在首页统计、开场与番剧页共用同一请求，保留 latest → immutable snapshot → API fallback 链路；成功结果保留 300 秒，失败不缓存，不中断其他消费者的请求。
- 首页不再为一个番剧数字等待远端；关于页使用原有 12 小时再验证，GitHub 请求有 4 秒超时。两页均可预渲染。
- 预取笔记 CSS、按实际 Next Image 规格预解码关于页封面。列表封面继续使用已有视口和尺寸预算，不提前下载整站图片、音乐音频或所有文章。
- Save-Data / 2G 跳过主动重资源预热，仍预取导航入口。直接进入相应页面仍按需加载。

Field 的障碍列表没有数量截断，布局采样为 10 Hz；后台不绘制。页面入场缩为 0.2 秒并遵守减少动态。关闭的笔记文件夹与手机目录不挂载子树，目录不同时自动预取大量文章。

## 本地测量与边界（2026-09-27）

Windows、Node 22.23.3、生产构建、Headless Chrome 154、Intel Arc / ANGLE Direct3D11；桌面 1440×1000 DPR 1。所有八个导航按顺序点击，记录 URL 提交、下一绘制机会及 PerformanceObserver 长任务。软件计时与窄屏仿真不代表所有真实设备、网络或生产 CDN。

修改前生产样本中，项目页同步长任务 **3378 ms**，小屋就绪 **4148 ms**；音乐首次进入同步长任务 **1560 ms**；关于页 URL 提交 **1156 ms**。这些是单次基线，不作为固定提速百分比。

修改后默认 Field 的首次开场：loading 347 ms → particles 2552 ms → ready 3073 ms，轨迹阶段 **521 ms**。GLB 与夜间图在 650 ms 发起，各一请求，压缩传输合计约 **1.80 MiB**；解压资产仍为 3.39 MiB。窄屏 390×844 样本轨迹 **517 ms**，确认第二阶段背景可见、页面隐藏，随后恢复文档滚动。

本地没有 Blob/Bangumi 凭据，因此番剧页验证的是错误降级界面；真实封面、快照延迟与移动 Safari 需要部署环境验证。外部音乐接口响应、GitHub 与用户网络不属于开场完成的硬前提。

## 全站优化验证（PR #39）

- 类型检查、完整 ESLint（0 错误，7 项既有警告）、73 项 Node 测试、Next 生产构建（245 页）。构建使用 `next build`，不执行图片上传。
- 缓存并发合并、失败重试、300 秒过期；真实模型 BVH 与原始 raycast 命中/距离一致。
- 全导航首次与重复访问；小屋实际 WebGL context loss 后卸载 canvas 并展开目录。
- 手机第二阶段的 Field 可见性及文档滚动；手机实际圆盘菜单逐个进入八页，无水平溢出且菜单自动关闭。普通模式、减少动态均没有进入粒子阶段；跳过开场在点击时显示内容，随后未重新遮挡。

## 刷新入口修复验证

- 本次重新通过修改文件 ESLint、Prettier、`git diff --check` 和 Next 生产构建（含 TypeScript，245 页）。上节的 73 项测试属于此前全站优化验证，本次未重新运行。
- 生产浏览器中首页首次进入与刷新均为 `loading → particles → ready`；保留旧 `hasSeenSplash=true` 后仍按同一路径执行。桌面首页刷新粒子阶段约 517 ms，390×844 窄屏首页首次进入约 506 ms。
- 直接进入项目页、刷新项目页与直接进入关于页均为 `particles → ready`，粒子阶段分别约 1005、997、977 ms。关于页站内导航回首页不增加启动阶段标记，保持 `ready`。
- 将真实关于页 HTML 放入同源 iframe，保留 inline bootstrap 并用 CSP 禁止外部脚本后，头像层 `display: none`、入口 `page`、阶段 `particles`，且没有 hydration 阶段标记，验证子页在 React 加载前不会闪现头像。
