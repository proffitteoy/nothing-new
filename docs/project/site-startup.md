# 全站启动与导航

## 现行启动协议（2026-11-25）

桌面首页使用「山湖图版」：中性浅白、湖蓝自然轮廓、中央显色和轻倒影，最后整体交叉淡入已有日间窗景。图版取自现有山湖素材；线稿是插画，不是 Alpha 滤过、地理测量或下载进度。它保持自己的宽幅构图，不做缩放入窗或逐像素配准。旧 Alpha HTML 保留为历史资产，首页不再请求 iframe 或监听其消息。

| 阶段 | 从首个 SVG 帧起算 | 行为                               |
| ---- | ----------------- | ---------------------------------- |
| 构图 | 0–0.25 秒         | 主要轮廓渐显；跳过按钮已可使用。   |
| 成形 | 0.25–0.85 秒      | 山体折线形成，山脊与湖岸保持明确。 |
| 显色 | 0.85–1.40 秒      | 中央山湖和倒影渐显，两侧保留线稿。 |
| 停顿 | 1.40–1.65 秒      | 保持完整图版。                     |
| 交接 | 1.65–2.40 秒      | 首页可用后进入 750ms 整体淡出。    |

首页提前就绪仍完整展示。1.65 秒时不可用则保持图版，每 50ms 检查一次，最迟在第 4 秒进入退出段，正常已 hydration 的控制器约 4.75 秒内释放页面。跳过直接结束；SPA 离开入口路由也结束，不在返回首页时重播。动画、监听和定时器在结束／卸载时清理。

### 本地验收

`npm run test:opening` 在本地生产预览运行后执行。四个桌面尺寸、冷／热缓存、慢网、图片延迟／失败与重试、无 WebGL、跳过、减少动态、受限网络、路由取消、移动分流及无 JavaScript 均生成 JSON 结果，正常首页另存关键帧和完整录屏。依赖和用法见 [脚本说明](../../scripts/README.md#首页开场验收)。证据默认写入忽略目录 `.sync/tmp-opening-rewrite/`。外部音乐、番剧和论文 API 使用本地空响应，真实山湖、室内图片和三维资源不替换为夹具。

2026-11-25 本地结果：Windows、Node 22.23.5、Chrome 158.0.8127.37 下，155 项单元测试、正式类型检查和 248 页生产构建通过；ESLint 0 错误，保留 3 条既有警告。浏览器 17 组场景通过，无未捕获页面异常。四种桌面冷缓存从首个 SVG 帧到可交互为 2.407–2.421 秒，热刷新 2.401 秒，80ms 延迟／1MiB/s 下载条件下 3.798 秒，延迟图片 3.334 秒，图片和 WebGL 均失败时 4.762 秒后释放；失败图片可实际重试恢复。

正常启动样本的帧间隔 P95 为 16.8ms，最大间隔为 133–150ms，仍观察到初始化阶段长帧；不据此宣称全程 60fps 或跨设备性能达标。录屏为 `.sync/tmp-opening-rewrite/cold-1440.webm`，原始时序与长任务见同目录 `report.json`。Safari、真实手机与人工美术验收未覆盖，未部署生产。

## 移除全局粒子后的合并修复

当前根布局通过 `getBlogEntryRoute()` 解析默认笔记地址，并将同一个 `blogHref` 传给 `SplashScreen` 与 `Navbar`，不能只给组件补一个硬编码默认值。`FieldScene` 只在 `/music` 挂载，其他页面没有粒子场；音乐页封面粒子独立显示，首页“性能交替”默认关闭且只切换音乐页的常规/谱场模式。启动流程不再等待 `fieldReady`，第二阶段改名为 `preparing`，只用于有上限的资源准备，不显示全局粒子。首页头像阶段、子页跳过头像、跳过按钮、9 秒 hydration 失败兜底和 noscript 可访问性保留。

下文包含移除全局粒子前的历史设计与测量，涉及 Field、`particles` 阶段或普通/谱场模式的内容不代表当前行为，也不能作为本次修复的运行证据。

## 启动顺序

1. 每次完整进入或刷新首页，都先展示头像、光环与进度动画。动画至少 2.2 秒；首屏可见图片的 `decode()`、字体及 Field 首帧参与就绪判断，资源等待最多 4 秒。进度条是开场动效，不代表下载百分比。
2. 首页第一阶段之后，以及直接进入或刷新其他页面时，隐藏页面控件，展示同一个全站粒子场景 0.5–2 秒。其他页面跳过头像动画，在粒子阶段有上限地等待当前页图片、字体、Field 和小屋状态；在 hydration 前根据入口路径决定可见层，避免头像闪现。重要资源提前完成时取短时长；超时后仍可浏览。没有第二个 Field 实例，没有在揭幕时集中创建效果。
3. 揭幕后恢复导航、内部滚动容器和播放器。手机只在第二阶段显示轨迹，进入页面后沿用原来的移动端背景策略与文档滚动。站内软导航保留已经就绪的布局，不重播开场；刷新和直接打开页面按入口执行：首页走第一、第二阶段，其他页面只走第二阶段。不再读写 `sessionStorage.hasSeenSplash`，旧标记不会绕过资源准备。

“跳过开场”立即显示页面，后台预热继续。`prefers-reduced-motion` 或显式保存的普通模式跳过第二阶段。新访客默认 Field，保留普通模式偏好；存储失败时仍能切换。HTML 中的 9 秒兜底与 noscript 样式避免 hydration 失败造成永久不可见。

## 哪些资源提前准备

- 共享导航清单的八个入口由 `router.prefetch()` 依次启动，手机无需先展开菜单。笔记直接预取服务端解析的默认文章，保留 `/blog` 原有跳转。Next 的 prefetch 没有完成 Promise，不把“已发起”当成“已就绪”。导航 Link 继续负责缓存失效后的预取。
- 小屋 JS 与 3.18 MiB 压缩源资源可在启动时预热；贴图解码、GLTF 解析和拾取 BVH 由挂载的 RoomScene 持有。2026-11-12 已删除无调用者的 CPU 预解析/60 秒待用缓存，后续访问仍从压缩资源缓存创建独立场景，失败可重试。离开路由释放 GPU、纹理、几何和索引，不共享已释放的模型。
- 原 Octree 构建存在秒级同步任务，改为 three-mesh-bvh 的间接索引，并在模型组之间让出主线程。真实 GLB 的双面射线测试与原始三角形 raycast 对照，避免以性能换取拾取错误。
- 音乐页代码提前导入，首次使用的两套着色器通过 `compileAsync()` 编译，后台暂停动画。无 WebGL 时保留播放器控制。是否能异步编译还取决于浏览器的 `KHR_parallel_shader_compile` 支持。
- 番剧 metadata 在首页统计、开场与番剧页共用同一请求，保留 latest → immutable snapshot → API fallback 链路；成功结果保留 300 秒，失败不缓存，不中断其他消费者的请求。
- 首页不再为一个番剧数字等待远端；关于页使用原有 12 小时再验证，GitHub 请求有 4 秒超时。两页均可预渲染。
- 预取笔记 CSS、按实际 Next Image 规格预解码关于页封面。列表封面继续使用已有视口和尺寸预算，不提前下载整站图片、音乐音频或所有文章。
- Save-Data / 2G 跳过主动重资源预热，仍预取导航入口。直接进入相应页面仍按需加载。

Field 的障碍列表没有数量截断，布局采样为 10 Hz；后台不绘制。页面入场缩为 0.2 秒并遵守减少动态。关闭的笔记文件夹与手机目录不挂载子树，目录不同时自动预取大量文章。
