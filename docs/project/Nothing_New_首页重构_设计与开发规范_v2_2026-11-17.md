## 0. 不可误解的设计命题

> 用户是在室内，透过一面真正具有空间纵深的宽窗，观察外部完整、连续的日间山湖景观。数学谱场不是额外发光的东西，而是一条作用于**已有场景物体**的运动规则。观者感知到的应是水、云或植被的细微响应，而不是“看见谱场”。

首页的主角是**完整的空间关系**，不是背景大图、发光线条、视差图层或导航特效。必须先让完全静止的画面成立，再引入运动。对某个元素若无法解释其在这一空间中的位置、材质、光照来源或作用对象，则默认**不实现**。

已确定的负面边界：**禁止**极光、铺满天空的轨迹、独立光雾、空中粒子、无对象的谱场绘制、整图重复叠放以制造伪景深、分离的水面反射贴片、弹出的页面截图预览、金属控制台式窗台。不得用这些效果作为“待调弱”的候选继续迭代。

## 2. 视觉目标：真正的窗户，而不是有边框的显示器

### 2.1 空间构图

采用**单一、固定的室内观察点**。视觉由三个明确层次组成：

1. **室内侧：** 左右墙面／窗洞侧壁、顶部窗洞内缘、底部真实窗台。三者是同一建筑开口的连续结构；厚度、阴影方向和材质一致。
2. **开口：** 一片无遮挡的大玻璃视域；不添加格栅、伪镜头光斑、移动反射扫描条。玻璃的存在主要靠窗洞、边缘与轻微反射暗示，而不是大面积高光。
3. **室外侧：** 一幅连续的日间山湖世界。远山、岸线和水面共享同一个成像关系；不因为鼠标移动产生山水错缝。

在 1440×900 先审阅构图，之后适配 1920×1080、1366×768、1280×800、1024×768 以及矮视窗。窗户应占据屏幕中央的主要面积，但**不固定百分比来牺牲窗洞感**。左右导航处于室内墙面，不进入景观画面。窗台存在实体深度，播放器只是安静地位于其上，不再像设备操作台。

### 2.2 日间色彩与光照

采用自然、清晰、克制的日间光照。室外景观保持其可信的蓝天、雪山、植被和湖水；室内墙面采用中性或略暖的浅色反射光，木质/石灰质/哑光涂层可作为审阅候选，**不预先认定某个装修风格**。窗洞右、左、上、下边缘必须服从同一主光方向。禁止整幅画面铺蓝灰滤镜、金属银边和大面积玻璃拟态。

当前授权日景 `public/home-window/convict-lake-day-study.webp` 可用于第一版静态校正；保留 `NOTICE-day-study.txt` 的来源和衍生声明。若素材本身妨碍空间真实性，可以替换，但需单独提审构图和授权。不得从多张不同透视的景观随意拼接。

### 2.3 静态视觉门槛（P0）

浏览器禁用动画、Canvas 和 WebGL 时，用户仍须明确感到“站在室内看向室外”。静态画面应满足：窗洞有可辨认的侧壁与内缘；窗台不呈操作台质感；湖面连续；雪山不是屏幕里的海报；两侧导航看起来属于室内；整屏没有一处需要通过运动来解释的异常元素。

**若 P0 静态视觉未经人工批准，不得开始谱场或视差实现。**

## 3. 页面结构与导航交互

### 3.1 信息架构不变

左侧仍为「项目、番剧、杂谈、笔记」，右侧仍为「论文、友链、关于、联系」。现有链接、页面路径、笔记实际入口、论文报告数据和联系动作不变。音乐继续使用唯一的根级 audio / MusicProvider，不自动播放；保留歌词、播放、暂停、切歌、进度功能。

### 3.2 导航原则

六个普通页面项（项目、番剧、杂谈、笔记、友链、关于）用清晰的文字/图标导航，**点击直接进入页面**；悬停只允许轻微状态提示，不弹出截图、不将网页缩略图塞入窗户空间。若保留“展开”的视觉形式，展开的也只能是标签文本、极简说明或导航自身的底板，不能是另一个页面的画面。

「论文」保留 `PaperMonitor` 的检索、报告和进一步阅读能力；「联系」保留 `ProfileActions`。它们可以使用统一样式的室内侧抽屉/对话框，且只在用户明确点击时打开。面板是功能界面，不伪装成窗外景色；打开时不改变窗外透视。必须保持关闭、Escape、焦点恢复、原生 dialog、读屏可达性与页面滚动控制。小屏或低高度下不可遮挡音乐全部操作。

### 3.3 删除项

删除首页对 `page-previews/*.webp` 的静态导入与首屏预解码依赖；删除 `SidebarPreview` 对六个导航项的引用，但**不要**误删其他页面仍然需要的共享组件。清理随之失效的展开定时器/固定状态，而不是留下不可达的交互逻辑。

## 4. 数学谱场：从“可见特效”改为“物体响应”

### 4.1 数学源保持独立

保留已有六模态参数、种子/相位和已有可见时间时钟；现有 `spectralDirectionAt` 表达的是流函数诱导方向的采样。**归一化方向不等于速度大小，轨迹密度不等于能量密度，方向场曲率不等于发光强度。** 不能把这些量偷换为“极光亮度”或“物理能量”。

使用下面的单向依赖：

```text
SpectralField (数学场；没有 UI / Canvas 依赖)
        ↓ 统一时间、坐标映射、采样
ObjectCoupling (物体类型 + 有效区域 + 响应律 + 强度约束)
        ↓
LandscapeRenderer (真实物体材质／几何的局部变化)
```

在代码中以对象材质（water / cloud / foliage）作为接入点，不允许存在面向天空的通用 `spectralMist` 或无对象发光图层。`SpectralTracerLayer` 可以继续服务其他页面或作为**开发调试可视化**，但不参与首页最终画面。调试模式不得出现在生产默认视图。

### 4.2 可检验的耦合定义

设数学方向场为 $F(x,t)$，对象 $m$ 有可见区域 $\Omega_m$、坐标映射 $\pi_m$、响应掩码 $\chi_m$ 和响应系数 $\lambda_m$。用于对象材质计算的驱动可写成

$$
U_m(p,t)=\lambda_m\,\chi_m(p)\,P_m(p)F(\pi_m(p),t),\qquad p\in\Omega_m,
$$

其中 $P_m$ 表示从公共场坐标到该对象局部切平面/参数域的映射。该公式是**实现接口约束**，不是宣称已有谱场严格描述真实流体力学。场的方向影响对象响应，强度由有界的材质参数给出，所有效果在几何边界处连续衰减。

每个接入对象必须同时交付：可解释的映射、零场对照、响应系数范围、边界连续性证据、前后帧对比。**无法回答“影响了哪个物体、该物体的什么属性、为何如此变化”的效果不予合并。**

### 4.3 首个唯一动态对象：湖水

第一轮只做湖水，暂不实现云、树、山体或光照联动。

- **基底连续：** 原始完整日景只提供一套共享的场景像素坐标；静态基础湖面与岸线不可拆成可独立平移的图片。
- **动态区域：** 仅湖面内部受场影响；使用湖面区域掩码，但该掩码控制的是**局部像素采样/法线响应**，不承担覆盖另一张全景图的任务。
- **具体响应：** 从水面图像的既有细纹理/法线扰动出发，让局部纹理采样沿 $U_{water}$ 作有界的缓慢平流，或让小幅法线变化随场方向演化。禁止在原图上绘制独立蓝紫反光带。
- **边界约束：** 岸线附近扰动幅度平滑趋于零，海拔/透视投影与岸线静态像素严格对齐；与山、岸、天空共享同一取景变换。
- **强度建议：** 从 1440px 视图下亚像素至约 1px 级的局部屏幕位移开始调参，而非默认大波浪；这是**候选预算**，须由审阅截图决定。
- **零场/静止对照：** $\lambda_{water}=0$ 时在视觉上还原完整静态景观；降低运动偏好或渲染不可用时同样还原静态底图。

首选技术路线是**单一景观输出**：一张基础纹理经统一 UV/屏幕坐标采样，只在湖水内部应用受场驱动的采样偏移；若使用 WebGL，输出由**一个**场景合成器产生，CSS 中不再另画一层完整景观和独立动态反射。静态退化时允许保留一张普通 `<Image>`，但静态和动态输出不可同时可见。原则上不需要完整 Three.js 世界；先验证能否用小型局部 shader 在同一底图内完成。

### 4.4 后续对象接入标准（非首版范围）

云只在存在可授权、与底图严格配准的云层几何/遮罩时才允许缓慢变形；植被只在能识别独立枝叶或冠层时才允许局部摆动。每个对象对同一场采用不同材质响应，但不得另造无关的运动噪声。如果素材不支持可靠分割，**宁可保持静止**。山体默认不变形；天空默认不显示可见谱场；所谓“极光”不属于当前产品需求。

## 5. 图像、层级与坐标系统

### 5.1 保持一套坐标映射

视口 $V$、底图 $I$、湖面掩码 $M$ 和场采样使用一套经验证的 `sceneToViewport / viewportToScene` 映射，缩放时保持单一裁剪矩形。像素、世界或 UV 坐标的转换要集中封装，不允许在 DOM 层用 `calc()` 平移 10px、在 Canvas 层另平移 6px 来“对齐”。

真实景深在单张图片中无法从纯 CSS 可靠恢复。**首版关闭景观分层视差。** 若将来提出景深需求，须先拿到可配准的深度图或合格分层资产，再单独做 POC，证明山水边界、反射和遮挡在整个相机位移范围一致。不能以“只移动几像素”豁免几何正确性。

### 5.2 画面层序（仅保留有真实职责的层）

```text
HomeScene
├─ RoomFrame                 室内墙面、窗洞、内缘；纯布局
│  └─ WindowOpening          唯一景观裁切边界
│     └─ LandscapeSurface    单次合成的完整山湖图像
│        └─ WaterResponse    景观内部局部材质处理；并非独立全景平面
├─ NavigationRail × 2       DOM 导航与必要功能面板
└─ WindowSill
   └─ MusicDock             复用现有音乐控制器
```

建议仅有一个权威的 `LandscapeSurface` 负责定义裁切、缩放与渲染状态。`RoomFrame` 不消费谱场；`NavigationRail` 不随风景动；`MusicDock` 不承担景观材质。玻璃若没有可信反射来源，保持无额外装饰层。

## 7. 迭代与 PR 划分（不得合成一个大 PR）

**PR-0｜止损与基线。** 截取现有生产页面作为“问题样本”；添加可回退的首页静态模式，禁止默认光雾/天空线条/独立湖面倒影，建立无动画、无 WebGL 静态兜底。记录当前加载、音乐与移动分流回归。此 PR 不声称重设计完成。

**PR-3｜水面谱场耦合。** 先提交场坐标与对象响应接口、零场对照，再做水面内部的小幅动态扰动。必须附 `F=0 / F≠0` 同时间图像、掩码边界证据、视频及资源测量。没有几何连续性证据不合并。

**PR-4｜性能、兼容与发布验收。** 浏览器/设备回归、资源释放、低性能静态退化，视觉对照审阅。部署采用预览环境 → 人工批准 → 生产发布；发现接缝或异常图层可立即切回静态方案。

云、植被或空间视差均不包含在本轮里程碑内，未来须独立提出视觉理由和几何证据。

## 8. 验收标准：用反证方法阻止“功能通过、画面恐怖”

### 8.1 静态空间（最高优先级）

- 在截图中不需解说就能辨认窗洞、实体边缘、室内外关系；没有显著金属控制台、卡片边框或投影仪感。
- 画面无未经授权的天空光、极光、散射粒子、镜头扫描光或整图调色叠层。
- 湖面、山体、岸线在 0 帧、任意停留时长、鼠标移动与窗口缩放后连续；不出现断层、重影、边缘漏色、两个时间状态的反射。
- 关闭 JavaScript 动态能力或启用 `prefers-reduced-motion`，仍获得完整静态画面、可用导航和音乐控制。

### 8.2 谱场作用的可验证性

- 将谱场响应系数设为零，**只应消失物体的局部动态响应**；图像色彩、景观几何、窗框、导航和原始湖面全部保持。
- 改变谱场时间/相位后，水面内部的扰动方向随数学场变化；不得只是一个与场无关的正弦波或随机粒子层。
- 给出被作用物体的区域、坐标变换、输入场、响应变量、幅值边界；测试证明水面掩码外像素不随谱场时间变化（允许经定义的压缩/抗锯齿容差）。
- 岸线附近动态采样偏移收敛至零；任何帧不得产生可见的水面切口。调试图可展示场向量，但生产画面不显示。

### 8.3 功能与性能

- 导航八入口可用；普通入口无截图预览；论文/联系面板可操作且正确关闭；键盘焦点顺序、屏幕阅读器标签和 Escape 合格。
- 保持唯一音频实例，不自动播放，切换页面后不出现双音乐或播放器失联。
- 维持现有 `Splash` 与图片就绪/超时约定；无 WebGL、低性能、背景标签页和资源释放时都可恢复静态模式，不空白、不泄漏 Canvas。
- 性能以实际生产构建在 1440×900、1920×1080、1280×800、1024×768、640×720 等目标视口复测；分别报告 FPS、主线程耗时、GPU/Canvas 缓冲理论尺寸、交互延迟。目标值必须先测基线再确定，不把旧光雾版本的 45fps 当新实现的验收证明。

### 8.4 交付证据和否决机制

每个相关 PR 附静态 PNG、代表性录屏、构图/裁剪对照、失败与恢复测试、浏览器环境、资源开销表。自动化只负责可测的几何与功能，**人工视觉审阅是强制门禁**。即使测试全部通过，只要仍像一个巨型显示器、导航突然出现无关网页画面或湖面明显裂开，即判视觉验收失败。不得以“数学模型是同源的”“FPS 达标”替代该判断。

## 9. 非目标与禁止的扩展

本轮**不做**完整三维地形重建、天气系统、昼夜循环、真实流体仿真、光线追踪倒影、动态极光、额外背景音乐系统、全站主题重构、复杂导航截图动画、无材料依据的分层视差。既有场数学不必为迎合照片改变。若当前技术难以可靠实现水面响应，可以先交付经人工认可的**纯静态观景窗**，不能以装饰性特效冒充完成。

## 10. 完成定义

这次重构成功，不是因为用户能看见“一个谱场效果”，而是因为用户首先看见**一个可信、安静、连续的窗外世界**；驻足之后，才发现水的运动有一种微妙、统一的内在规律。关闭全部动态，这依然是一扇窗。打开动态，世界仍然是同一个世界。
