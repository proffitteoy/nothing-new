# 首页个人介绍区更新与验收

#47 将 `ProfileCard` 从毛玻璃卡片改为开放式个人身份区。基线为 `deeb493`，设计依据是[完整原稿](<./frontend refactoring.md>)的「二、全站视觉系统」「5.1 第一屏」「九、交互反馈」「十二、最终首页」，以及[导航视觉规范](./navigation-renewal.md)。个人内容、数据来源、首页 7/12 与 5/12 分栏保持不变。

## 原稿与实现对照

| 原稿要求                 | 本次实现                                                                                             |
| ------------------------ | ---------------------------------------------------------------------------------------------------- |
| 小号栏目眉题、大字号姓名 | `PERSONAL JOURNAL / 00`；姓名使用本地 Newsreader／思源宋体等回退，桌面 96px、手机 72px、窄屏 60px    |
| 独立头像与轻微不对称构图 | 姓名向下错位，头像置于右侧留白；尺寸依次为 96／80／68px，继续使用原有 Next Image 与 `/avatar` 链路   |
| 简介原样保留             | 直接读取 `siteConfig.bio`，15–16px、1.75 行高，自然增高，无省略或行数限制                            |
| 出版物式元信息           | 四项统计使用 `dl`，数字在上、标签在下，以细线与留白分隔；320px 使用 2×2，其余验收尺寸使用四列        |
| 底部社交入口             | GitHub 为安全外链，邮箱／QQ／微信为原生按钮；44×44px 点击区域，中文可访问名称，独立于 `/about` 链接  |
| 减少大面积玻璃           | 移除原来的边框、圆角面板、模糊、阴影与整卡缩放；局部纸张色底层在四周淡出，确保真实插画背景上的可读性 |
| 克制的交互反馈           | 颜色反馈 180ms，无旋转或计数动画；减少动态效果时禁用局部过渡，保留全部操作                           |

局部 CSS Module 采用导航已验证的日夜 token：纸张 `#F8F7F3`／`#141923`、主字 `#252936`／`#E9EAF0`、次字 `#626875`／`#A1A7B5`、强调与焦点 `#625EB0`／`#A4A0EE`、细线 `#DDDDE2`／`#343A48`。相比原稿候选值，日间次字与强调色沿用导航较深的版本以改善小字对比度；没有请求在线字体或修改全局样式。

笔记、杂谈和音乐计数仍来自原有 props，番剧仍由 `loadAnimeSnapshot()` 的 `snapshot.items.length` 异步提供；未知或失败显示 `—`。复制操作等待 `navigator.clipboard.writeText()` 成功后才提示成功；拒绝访问或浏览器缺少该 API 时使用现有 Toast 显示失败。外层保留 `data-field-obstacle`。

## 隔离预览与截图

使用 Node 22 与 npm 10+，在本 PR 分支运行：

```powershell
npm.cmd ci
npm.cmd run dev -- --hostname 127.0.0.1 --port 3147
```

访问 <http://127.0.0.1:3147>，等待原有开场或点击跳过；通过首页「昼夜交替」切换主题。这个预览只运行在本机，不需要生产 Blob 凭据，也不改变线上部署。若 PR 有自动 Vercel Preview，可从 PR Checks 进入；没有自动 Preview 时按以上步骤复现。

Python Playwright 是可选验收依赖，安装方法见[导航验收文档](./navigation-renewal.md#复现截图与交互检查)。保持预览运行后，在第二个终端执行：

```powershell
python scripts/profile-preview.py --stage after --output "$env:TEMP/profile-47"
```

脚本对 320、390、768、1280、1440px 的日夜真实首页分别保存完整视口和组件截图，再运行功能检查。输出必须显式指定，建议放在仓库外；二进制截图不提交到 Git。支持 `--url`、`--browser` 指定已有 Chromium，以及 `--check-only` 仅运行检查。

改造前对照需在基线 `deeb493` 的独立 worktree 启动旧版站点，再从当前分支调用同一脚本，并使用 `--stage before --url http://127.0.0.1:旧版端口 --output 同一输出目录`。不能在新版页面上使用 `before` 标记。基线与新版目录分别位于输出目录的 `before/` 和 `after/`。

| 对照对象               | 两个目录中对应的本地文件                              |
| ---------------------- | ----------------------------------------------------- |
| 桌面日间／夜间         | `home-1440-light.jpg`、`home-1440-dark.jpg`           |
| 手机日间／夜间         | `home-390-light.jpg`、`home-390-dark.jpg`             |
| 窄手机、平板、较窄桌面 | `home-320-*.jpg`、`home-768-*.jpg`、`home-1280-*.jpg` |
| 组件完整高度           | 同尺寸的 `profile-*.png`                              |

所有验收截图使用真实资源与接口；音乐、番剧、歌词和时钟可能随时间、网络与本地凭据变化。为测试番剧未加载／成功／失败、头像失败和复制拒绝，功能检查会在单独的浏览器 context 中注入故障或响应夹具；这些夹具不用于视觉截图，也不写入网站代码或数据。

## 验证记录与边界

检查包含原始姓名与简介、Manifest／配置对应的三个计数、番剧占位与异步计数、头像正常／失败时的布局、五种宽度无横向滚动或文字裁切、姓名与头像不重叠、桌面与播放器不重叠、44px 操作区域、GitHub 目标、原生剪贴板成功、权限失败和 API 缺失、Tab／Enter／Space、手机触摸、焦点外框、减少动态效果，以及长简介自然增高。

工程检查运行 `npm run lint`、`npm run typecheck`、`npm test` 和完整 `npm run build`。当前仓库原有 ESLint 警告位于其他文件，正文中已有中文数学模式的 KaTeX 警告；不属于本组件的修改范围。独立 worktree 未配置 Blob，构建图片同步会明确跳过，不上传图片。

本次在 Node 22.23.4 下完成：lint 为 0 错误、7 项既有警告；类型检查通过；现有 87 项测试通过；完整生产构建生成 250 个页面。Chromium 在开发预览与生产预览均通过上述布局、交互和故障检查，生产预览重新生成了五种尺寸的日夜截图。原版与新版的视口／组件截图共 40 张，仅保存在本地。

本地缺少 Blob／Bangumi 凭据时，真实番剧计数显示 `—`，成功取数另由功能夹具验证。开发模式仍可观察到既有 `PageTransition` 在减少动态效果下的 hydration 属性提示；本次没有改动该组件。音乐和歌词来自原有实时接口，前后对照不保证动态内容完全同步。

本 PR 仅交付个人介绍区，播放器、模式切换、周报、全局背景、导航、首页整体网格与部署设置均未修改。浏览器检查不能代替 iOS／Android 实机和人工视觉验收；人工验收通过前不合并 `main`。
